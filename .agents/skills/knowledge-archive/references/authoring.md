# 内容组织方法

这些是可选方法，不是每个话题必须包含的章节。根据对象、问题与读者基础选择。

## 先确定理解目标

明确读者希望解释的现象、需要做的判断及已有知识。划定范围与核验时间，优先回答有信息增量的问题。广度调研通常形成分类、脉络和比较；深度探索通常沿一个问题追踪机制、假设与证据。两者可以组合。

## 用证据推动组织

- 用机制分层或概念地图拆开容易混淆的对象，说明接口、职责与边界。
- 沿关键转折组织技术脉络，解释什么需求促成了变化；避免把发行日期列表当作发展解释。
- 比较对象时先给共同维度与条件，再谈差异。可以用表格，也可以围绕案例逐个分析。
- 从一个具体场景、故障或反例展开：输入是什么，机制如何工作，输出是什么，在哪个条件下结论失效。
- 有可验证假设时给源码路径、复现步骤或实验设计；没有实测时明确呈现为设计或静态分析。
- 保留尚未解决的问题以及下一步可执行的探索线索，但不必在每个章节添加固定总结。

重要结论附近放来源。记录版本、日期和适用条件，区分一手事实、作者自述、论文报告结果与自己的推断。没有共同协议的性能数字不做统一排名。

## 两种独立产物

Markdown 可用阅读路径、清晰层级、对比表、近旁引用及例子支持细读。按主题安排摘要、机制、证据、案例、取舍与来源，不要求统一的章节数量或标题。

HTML 从同一证据构建自己的理解顺序。选择能解决理解困难的视觉手段：因果图解释影响，时序图解释过程，分层图解释职责，时间线解释演进，案例切换解释条件差异，参数推演解释变化。不要为了视觉丰富而重复堆卡片或添加无关交互。

图示配文字解释，静态 HTML 保存正文、主要图示和默认结果。模拟或合成数据要标注假设，真实测量保留条件。复杂机制允许分步骤解释，但单个事实不必制作控件。

页面外观使用 `templates/interactive/`，主题自己的 CSS/JS 只承担特定图示及控件。模板控制布局、字体、间距、共同导航和页尾，不控制知识内容。

## 沿旧内容修订

先理解旧材料的论证与引用，再检索变化。对新增进展判断它是否改变分类、机制、默认行为、比较或建议。将新证据融入对应解释；不要只在文件末尾附“近期动态”。删除过时或无用重复，修正已被证伪的判断，保留仍然有效的材料。

在新双资料中简要注明本轮变化及核验范围。可以使用修订说明、正文近旁说明或适合主题的其他方式，不强制固定“更新章节”。记录哪些关键来源重新核验；局部更新不能用一个新日期暗示整份旧引用都已复查。

若重新核验后没有机制性变化，可以说明核验范围及保持结论的依据。证据不足时说明无法确定的点，不制造“新进展”来填满新版本。
